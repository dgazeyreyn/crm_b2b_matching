Project Overview

This is an end-to-end analytics engineering project — a dbt + BigQuery pipeline (staging → intermediate → marts → platinum layers, 25 models) built to diagnose what's driving customer complaints about a B2B data-matching and enrichment product.

Business Problem

Companies that run their sales and marketing off a CRM need that data to stay current as businesses merge, rebrand, or shut down. A common fix is an enrichment service: an algorithm matches each CRM record to its corresponding company profile in an external database, then keeps that record synced. The value only holds if two things are true — the match is correct, and the underlying company data is accurate. Support and account teams have recently flagged a rise in match-quality complaints, and customer health metrics point to real retention risk. This project investigates what's actually behind those complaints, and what to do about it.

Verdict

Three fixes, prioritized by where the evidence points hardest.

Reconciled against an independent case-study analysis of this same dataset — both investigations converge on the same root issues from different angles.

01 — Algorithm

Recalibrate confidence to reflect geo validity

Confidence scores don't separate right matches from wrong ones (95.4 vs 95.3 median) and are already structurally lower for SMB (74 vs 96) without being acted on. Add geo-consistency as a scoring input, not just a downstream QA check, and consider hard-failing impossible city/region combinations.

02 — Validation

Fix the review process before trusting it again

17% true accuracy, and 85% of real defects waved through, means this process cannot currently be relied on as a safety net. Blind validators to the confidence score, retrain on geo-consistency rules specifically, and re-audit last quarter's "Correct" labels to size the historical exposure.

03 — Customer Success

Treat SMB as the early-warning segment, not the low-priority one

SMB carries 3× its proportional share of tickets, at higher severity and frequency, on matches that were already less confident going in. Prioritize an SMB-facing fix and proactive outreach now — ENT/MM haven't surfaced the same complaint volume yet, but they're sitting on the same underlying defect rate.

04 — Data Governance

Investigate company-record region assignment as its own workstream

83% city→region inconsistency, spread almost uniformly across all six regions, looks less like noisy data entry and more like a systemic assignment or ingestion defect. It doesn't appear to be causing the match-level mismatches in Exhibit A — treat it as a separate root cause requiring separate investigation.
